# Manual live test results: 2M documents from Amazon OpenSearch Service to Pinecone

Run on 2026-10-06 against a customer-like setup: the data was loaded into an Amazon
OpenSearch Service domain first (`tools/opensearch_dataset/`), then migrated with pcmigrate
through OSIS and Glue into one Pinecone index with one namespace per source index. Code:
PR #14 (`phase5-opensearch-dense`), with the fixes listed at the end applied during the run.

## Setup

| Item | Value |
| --- | --- |
| Dataset | `pcmigrate-data/2M_2indexes`: 2 parquet files x 1,000,000 rows, 1,024-dim unit-norm vectors, 13 metadata fields (Amazon reviews), 1,000 queries per index with exact top-100 cosine ground truth |
| Source | domain `pcm-passages-2m`, OpenSearch 2.19, 2 x `r6g.2xlarge.search`, 200 GB gp3 each; indices `index1`, `index2` (2 shards, 1 replica, `knn_vector` hnsw/lucene/cosinesimil, m 16, ef_construction 128, ef_search 100) |
| Load into OpenSearch | `seed_opensearch.py load` from a laptop: 2,000,000 documents in 914 s (2,190 docs/s), counts exact |
| Migration | `migration_id: passages-2m-01`, `bucket: pcmigrate` with `bucket_mode: adopt`, `export_mode: osis_glue`, OSIS 2 to 8 OCUs, Glue 5.0 8 x G.1X |
| Target | Pinecone serverless index `passages-2m` (cosine, 1,024 dims, us-east-1), namespaces `index1` and `index2` |
| Mapping | generated by `introspect --source opensearch --table index1 --table index2`; `change_capture.tier: none`; default id template `index#{_id}` |

## Stage timings

| Stage | Duration | Notes |
| --- | --- | --- |
| provision | 2 min | base stack (adopted bucket) plus OSIS pipeline, Glue job, roles |
| prepare_index | 7 s | index created |
| export | 32 min | T0 recorded, armed OSIS pipeline released, scan of 2M documents into `raw/`, Glue transform to canonical Parquet: 1,000,000 rows and 0 rejects per index |
| transform | 31 min | pre-validation and duplicate-vector routing on the runner (laptop) |
| emit | 22 min | import Parquet files |
| import | 16 min | 1,924,936 records by bulk import plus 28,560 and 46,504 duplicate-vector upserts through the data API |
| validate | 21 min | after the id-scan fix; the first attempt was on pace for 2 h 10 min |

Transform and emit ran on a laptop over the internet; on the in-VPC runner they are
bandwidth-bound in the other direction and should be several times faster.

## Duplicate vectors

28,560 documents in `index1` and 46,504 in `index2` carried a vector identical to another
document's (the same review text embedded more than once). Bulk import silently drops such
records, so transform routed them to `manifest/duplicates/` and import upserted them through
the data API afterwards; both namespaces finished at exactly 1,000,000 records.

## Validation (pcmigrate validate stage)

Every check passed; `s3://pcmigrate/passages-2m-01/manifest/validation.md` holds the table.

| Check | index1 | index2 |
| --- | --- | --- |
| Count parity | 1,000,000 / 1,000,000 | 1,000,000 / 1,000,000 |
| Vector fidelity (1,000 sampled ids) | min cosine 0.9999999, 0 missing | same |
| Metadata fidelity (1,000 sampled ids) | 0 differ | 0 differ |
| Recall@10 vs exact `script_score` kNN (200 queries, threshold 0.95) | 0.976 | 0.9515 |
| Filter parity (20 most common filters, overlap@10) | 1.0, 20 of 20 exact | 0.985, 17 of 20 exact |
| Id diff (full id set) | 0 missing, 0 extra of 1,000,000 | 0 missing, 0 extra of 1,000,000 |

The recall values measure Pinecone's approximate search against exact source kNN; the id
diff proves nothing was lost. Index2's lower figure comes from its 46K identical vectors:
when the query is a stored vector, ties decide which duplicate id lands in the top 10.

## Recall against the shipped ground truth (`seed_opensearch.py recall`)

Same exact top-100 cosine ground truth, 300 queries per index, run against both systems.

| Metric | OpenSearch (source) | Pinecone (migrated) |
| --- | --- | --- |
| index1 recall@10 | 0.927 | 0.980 |
| index1 recall@100 | 0.917 | 0.978 |
| index2 recall@10 | 0.860 | 0.977 |
| index2 recall@100 | 0.848 | 0.966 |
| Latency p50 / p95 | 51 to 57 ms / 129 to 138 ms | 49 to 52 ms / 124 to 132 ms |

Pinecone returns 98 of the true top 100 for index1 and 97 for index2; the source domain
(lucene HNSW, ef_search 100) returns 92 and 85. The gap between the two indices is 0.3
points on Pinecone and 6.7 points on OpenSearch. Latencies are single-client round trips
from a laptop (Pinecone: one query per namespace), not a load test.

Summary for a customer: every record arrived, vectors and metadata are byte-faithful, and
approximate recall improved from 0.93 / 0.86 to 0.98 / 0.98 at k=10 with similar latency.

## Problems found during the run, all fixed on the branch

| Symptom | Cause | Fix |
| --- | --- | --- |
| provision: `BucketAlreadyExists` | the base stack always created the bucket | `bucket_mode: adopt` reuses an existing bucket and its storage integration |
| provision: log group `AccessDeniedException` on the KMS key | the key policy did not allow `logs.<region>.amazonaws.com` | key policy with the CloudWatch Logs statement |
| provision: OSIS `Exactly one non "pipeline" source is required` | one `opensearch` source per index | one source for all indices with per-index routed S3 sinks |
| validate on pace for over 2 hours | id scans sent `_source: []`, which returns whole documents | `_source: false` (1.4 min per 1M ids instead of 47) |
| OSIS `ValidatePipeline` rejections (found before the run) | `s3.buffer_type`, `connection.insecure`, `SystemExit` from the Glue script | removed; the script no longer calls `sys.exit` |

Remaining slow leg: Pinecone id listing at 100 ids per page (about 17 minutes per million
ids per namespace during the id diff). Parallel listing by id prefix is the planned fix.

## Commands used

```sh
cd pcmigrate-runs/passages-2m && set -a && source ../../pcmigrate/.env && set +a
export OPENSEARCH_URL=https://<domain endpoint>
alias P="uv --project <repo> run pcmigrate"
P introspect --source opensearch --migration-id passages-2m-01 --index passages-2m \
   --table index1 --table index2 --window 60 --out ./pcmigrate-out
P approve --approver <email> --out ./pcmigrate-out
pulumi login --local && export PULUMI_CONFIG_PASSPHRASE=<passphrase>
P run --until provision
P resume --until validate
cd <repo>/tools/opensearch_dataset
uv run seed_opensearch.py --config configs/2m-2indexes.yaml recall --target opensearch --queries 300 --k 10,100
uv run seed_opensearch.py --config configs/2m-2indexes.yaml recall --target pinecone --queries 300 --k 10,100
P teardown --yes
uv run seed_opensearch.py --config configs/2m-2indexes.yaml delete-domain --yes
```
